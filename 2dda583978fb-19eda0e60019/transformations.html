Methodology · release 2dda583978fb-19eda0e60019

Transformation specification

Release 2dda583978fb-19eda0e60019. This page specifies every transformation from the published files to the released tables, with the rule, the reason and the code that implements it. It is written for engineers moving the proof of concept to scheduled pipelines on live data. Every source, file, mapping and parameter below is generated from the configuration the build used, so it cannot drift from the code. Decision numbers (D-nnnn) refer to the decision log, which gives the full reasoning.

1. Layers and invariants

Layer Holds Written by Rule
L0 raw Published files exactly as downloaded, with SHA-256 cypneed ingest Write-once; a new version goes in a new dated folder. API queries are saved beside responses. Rebuilds never call APIs.
L1 staged One long Parquet table per published table cypneed stage Values kept as published text; labels kept; non-England rows kept; file totals checked.
L2 harmonised fact_<level>, fact_other_geography, dimensions cypneed harmonise Observed values only: England only, current codes, standard age bands; nothing imputed.
L3 derived derived_<level> cypneed derive Rates, intervals, smoothing, percentiles, conversions. Never overwrites L2.
L4 serving serve_*, profile_* views, release files cypneed serve, cypneed release Display layer; fallbacks are display only.
L5 composites l5_* tables cypneed composite Experimental; reads L2–L4 read-only.

Invariants that every pipeline must keep:

  1. Published figures win. A value published at a level is used as is; a sum of smaller areas is only used where nothing is published, and any difference is written to reconciliation.
  2. Counts move between geographies, rates never do. Rates are recomputed from summed numerators and denominators.
  3. Nothing is imputed. A sum with any suppressed or missing part is NULL with a null_reason and bounds.
  4. No value is pushed down from an area to the areas inside it.
  5. Every row carries lineage (source_file_id, lineage_key) and the snapshot_id (code commit + data hash).
  6. Determinism. Rows are sorted before floating-point sums, and Monte Carlo runs are seeded, so a rebuild gives identical content (gate 17).

3. Rules used by many sources

3.1 Geography

  • Hierarchy: LSOA21 → MSOA21 → LAD (April 2025) → UTLA (April 2025) → England. Each LSOA's and MSOA's parent is proven from Output Area membership and checked against full-resolution boundaries (99.9% of area inside the assigned parent).
  • Code successors (config/geography.yaml): an old code is relabelled to its successor only where the new code is absent from that series and boundaries are identical (D-0036, D-0060).
  • Other geographies are classified against the hierarchy by membership units (D-0054 onwards): coterminous (relabel), nests_within (sum when the parent is fully covered), contains (no conversion; the containing value is a labelled fallback), overlaps (T5).

3.2 Symbols, suppression and missing values

Each source's symbols are listed in its section below with the null_reason they map to and the most they can hide. A cell with a symbol is stored as NULL with the symbol in source_code. A sum is NULL if any part is NULL: suppressed (with count_lower, count_upper, n_suppressed) or incomplete. Absent rows are read as 0 only where the source is proven to list every non-zero case (D-0066 EHC plans, D-0084 asylum support, D-0048 police, children's homes).

3.3 Age bands

Populations are held by single year of age; a denominator band is the exact sum of the single years covering the numerator band. Source bands are kept as published (src_*) and never split.

3.4 Rates and confidence intervals (T7)

For count x and denominator n: rate = x / n × multiplier (100, 1,000 or 10,000 per indicator). The denominator must match area, age band, sex and ethnicity classification; stock measures use the population nearest the reference date, flow measures the mid-period population, and the gap must not exceed max_denominator_gap_days.

  • Wilson score (proportions), z = 1.959964, p = x/n: centre = (p + z²/2n) / (1 + z²/n); half-width = z·√(p(1−p)/n + z²/4n²) / (1 + z²/n). Limits are clipped to [0, 1]; x = 0 gives lower 0, x = n gives upper 1.
  • Byar (event rates): lower count = x(1 − 1/9x − z/3√x)³ (0 when x = 0); upper count = (x+1)(1 − 1/9(x+1) + z/3√(x+1))³; each divided by n and multiplied.
  • Reliability: low_reliability when x < min_reliable_numerator or n < min_reliable_denominator.
  • Undefined rates are NULL with a reason: zero_denominator, numerator_exceeds_denominator, denominator_suppressed, no_matching_denominator, denominator_period_gap.

3.5 Smoothing and comparability (T8, T9)

  • Marshall global empirical Bayes per indicator and level: m = Σx/Σn; s² = Σn(r−m)²/Σn; φ = max(s² − m/n̄, 0); Cᵢ = φ/(φ + m/nᵢ); EBᵢ = m + Cᵢ(rᵢ − m).
  • Percentile = (average rank − 1)/(N − 1) × 100, ties averaged, NULLs excluded; z-score uses the population standard deviation. Areas are sorted by code before any sum (determinism).

3.6 IoD summaries (T6c)

MSOA score = Σ(LSOA score × population)/Σ population (children 0–15 for IDACI, total population otherwise); share in decile 1 = population in decile-1 LSOAs / population. Ranks and deciles are never averaged. Validated against MHCLG's published LAD and UTLA summaries (gate 13).

3.7 Fallbacks and the publisher's method

  • Fallback (sql/fallback.sql): where a measure exists only for an area that wholly contains a council, that value is shown for the council with is_fallback = true. Never used in derived values, profiles or composites.
  • Publisher's method (publisher_method_fill): a published percentage is computed for areas the publisher leaves out, only after the stated method reproduces every published value to 1e-9 (D-0085).

6. Moving to live pipelines

  • One run, one snapshot. Keep the snapshot model: a run is defined by the code commit and the hashes of its input files, and writes a complete new set of tables. Do not update tables in place.
  • Parameters, not code. Periods (period_to_take, period in the maps), file URLs and file keys live in config/sources.yaml and config/category_maps.yaml. A new publication should mean new config entries, not new code, unless the file layout changes.
  • Fail fast on layout change. Staging finds columns by their published labels and checks totals and row counts (T2). Keep these checks: a renamed column or a missing row must stop the run, not produce wrong values.
  • Port the QA gates as data tests. Gates 1–19 are pytest checks over the output tables; each maps to a data-quality rule (keys, England only, conservation, suppression integrity, denominator match, ranges, reconciliation, serving completeness, reproducibility).
  • Things that are manual today: finding each new file (principle 11: verified URLs only); reading a new release's data guidance for symbols and rounding (config/suppression_codes.yaml); the NDTMS gap (D-0091); deciding whether a changed published figure is a revision.
  • Mapping to Microsoft Fabric: L0 as files in a lakehouse (pipelines or Dataflows to fetch); T2–T9 as notebooks writing one Delta table per layer table; L4 views as views or Delta tables; the composite step as a notebook with the same seed; the QA gates as a notebook that blocks publication when a rule fails.
